## 1. Isomorph rejection — VERIFIED (proof + exhaustive check n <= 12, planted n <= 9, n=17/18 prefix to level 9)

**Claim as implemented.** (a) Every node of the search tree is a weighted forest with pairwise-distinct edge weights (weights
are strictly increasing along a root path: `t` is the least value not in `R`, and it enters `R`). (b) The parent of a
forest is the forest minus its maximum-weight edge (= the last edge added). (c) `Aut(P)` of a distinct-weight forest `P`
without isolated vertices is generated by the endpoint swaps of its single-edge components. (d) The engine's child set of a
labeled parent `P'` = one representative per `Aut(P)`-orbit of extensions: `elig` drops the larger-index endpoint of every
2-vertex component (`popcount(cm)==2 && ctz(cm)!=i`), joins run over unordered pairs `x<y` of eligible vertices in
different components, attachments over eligible `x`, and `new` is unique.

**Proof of (c).** Let `phi` be a weight-preserving automorphism. Weights are distinct, so `phi` fixes every edge setwise.
If edges `e != f` share a vertex `v` then `phi(v) in e ∩ f = {v}`. In a component with >= 2 edges every edge has an endpoint
of degree >= 2 (else the edge is its own component), so every vertex incident to a degree->=2 vertex is fixed, and then the
other endpoint of each fixed edge is fixed: the whole component is pointwise fixed. A single-edge component admits exactly
the swap. Isolated vertices do not exist in the engine (`V` grows only through `attach`/`new`, both create incident edges).
Hence `Aut(P) = Z_2^{#single-edge components}`, acting independently on distinct components. This is the situation *before*
the merge; the "moment two components merge" is irrelevant: after the merge the component has >= 2 edges and its swap
disappears from `Aut`, which the engine recomputes at every node from `cm` (no cached automorphism state).

**Exactly-once.** Induction on the level. Suppose level-k nodes are pairwise non-isomorphic and cover every abstract
forced forest with k edges. Let `G` be an abstract forced forest with k+1 edges, `e` its max edge, `P = G - e` (a forced
forest, generated once as `P'`). Two extensions `P'+(x,y,t)`, `P'+(x',y',t)` are isomorphic iff some `phi in Aut(P)` maps
`{x,y}` to `{x',y'}` (an isomorphism of the children fixes the unique max-weight edge and restricts to an automorphism of
the parent). Since `Aut(P)` is the product of the swaps of the (distinct) components of `x` and of `y`, "smaller endpoint
in each single-edge component" is a complete and irredundant set of orbit representatives for joins, attachments (orbit of
`x`) and `new` (trivial). Children of non-isomorphic parents are non-isomorphic (their parents would be isomorphic). Hence
exactly one representative per abstract forest at level k+1. Note the argument needs the labels only through "the smaller
label of a 2-vertex component", which is what `ctz(cm)` computes; the appearance-order labeling is otherwise arbitrary.

**Computational check (independent code).** `tests/referee_forest_enum.py`: `brute` generates *all* labeled
join/attach/new children of every node (no symmetry rule), keeps a child iff its full distance multiset (recomputed from
scratch by BFS) is duplicate-free and inside the target, and de-duplicates each level by the canonical form
"sorted multiset of per-vertex sorted incident-weight tuples" (a complete invariant for distinct-weight forests without
isolated vertices: vertices are recovered as the sets, edge `w` joins the two sets containing `w`). `enginerule` applies
the engine's rule (appearance-order labels, smaller endpoint of a 2-vertex component, `x<y`) with **no** dedup and counts
canonical-form collisions.

## 2. Forcing rule in the forest setting — VERIFIED

Invariant: a search node `F` is *closed* in a Leech tree `T` (target `FULL`) if `F = {e in T : w(e) < t_F}` with
`t_F = min(FULL \ D(F))`. Root: `F = ∅`, `t = min FULL`, no edge of `T` has weight below the smallest distance. Step:
`t_F ∉ D(F)`; in `T` the value `t_F` is a distance; a realising path with >= 2 edges has all weights `< t_F`, hence lies in
`F`, contradiction; so `t_F = w(e)` for a unique edge `e ∈ T \ F`, and `F' = F + e` is closed for `t_{F'} > t_F`
(an edge with `t_F < w(f) < t_{F'}` has `w(f) ∈ D(F')` realised by a path of `F'`; distances of `T` are distinct, so that
path is `f` itself). `e` enters as join / attach / new according to how its endpoints meet `V(F)` — the isolated edge is
needed exactly when both endpoints of `e` carry no lighter edge; the engine allows it whenever `V+2 <= n` (necessary
since `F' ⊆ T` has <= n vertices) and it is never *required* otherwise. `F'` passes every child test (its distances are a
subset of `T`'s), the parent-level tests (`t + w_max <= N`: both edges lie on a common path of `T`; `V <= n`), so the
root path of `T` is in the tree and, by Section 1, `T` is counted exactly once. Custom targets: `t` ranges over
`FULL` only (`lowestMissingIn(FULL,…)`), correct since edge weights are distances.
Empirical (independent of the forcing lemma): section D — forest nsol == Σ_topologies (labelings by a plain
edge-by-edge DFS over target values with no forcing) / |Aut| for all 20 planted/standard instances n=5..9, plus the 5
multi-solution targets found (n=4 standard: 2; n=6, n=8 targets with 2 non-isomorphic solutions: 2 = 2).

## 3. Termination / covering / vertex bound — VERIFIED

`t > N` means every target value is realised by a distinct within-component distance; `#realised = Σ_C C(|C|,2) <=
C(V,2) <= C(n,2) = |FULL|`, equality iff one component on n vertices, so `ne == E && V == n` is redundant but harmless
(and it makes the check correct for degenerate custom targets with `|FULL| < C(n,2)`, where the engine correctly returns
without counting: any further edge would create an unrealised new distance). `ne >= E && t <= N` is dead
(`V - ne = #comp >= 1` forces `V = n`, one component, all `C(n,2)` distances realised, contradiction — so this line never
fires). The "budget" line never fires either: `#comp - 1 + (n - V) = (V - ne) - 1 + n - V = E - ne` identically
(each edge type reduces the deficit by exactly 1: join `-1`, attach `-1`, new `+1 - 2`), as the doc says. Forests never
exceed n vertices (`attach` needs `V < n`, `new` needs `V + 2 <= n`), matching `F ⊆ T`. Off-by-one audit of `shl`
(`q = s>>6`, carry `w[j-1] >> (64-b)`), `lowestMissingIn(FULL, 1, N)`, `N > 64*NW-2` guard, `n > MAXV-1` guard
(`cm` is `u32`, `MAXV = 20`, `(2u << x) - 1` for x <= 18): all fine; planted targets with max up to 166 (`NW=3`) and
420 (`NW=8` build) exercise the upper words.

## 4. Prefilters — VERIFIED (each a necessary condition, and jointly exact)

* `elig`: `hiD[i] + t > N` — `hiD[i] + t` *is* a new distance (farthest vertex of comp(i) to the new neighbour);
  `D0[i] << t` must avoid `R ∪ FULL^c` — these are exactly the new distances between comp(i) and the new neighbour, a
  subset of the new distances of any join/attach at `i`. Necessary for both endpoints of a join and for the attachment point.
* per-translate early exit in `tryAdd`: `sh + hy > N` (largest distance in the translate), `T ∩ (R ∪ FULL^c)`,
  `T ∩ U` (a distance obtained twice); within a translate the values are `sh + D0[y]`, distinct because `D0[y]` is a set of
  distinct distances (all realised distances are distinct by construction). Both branches (`ncx <= ncy` or not) compute the
  same union `U`. Necessary.
* `t + ew[ne-1] > N` (sum rule): the next edge (weight `t`) and the heaviest edge lie on a common path of the final tree,
  whose length is a distance `<= N` (= max target for custom targets). Necessary. Empirically it never fires for n <= 12
  nor in the n=17/18 prefix (Python `sumprune=False` gives identical counts), i.e. it costs nothing and prunes nothing.
* Joint exactness: the Python `brute` enumerator uses none of these filters (only the definition "all distances distinct
  and in the target") and reproduces the engine's per-level counts exactly (Section 1), so no valid child is ever dropped.
  Planted witnesses n=6..18 are found (Sections 6, 8).

## 5. Sharding — VERIFIED (partition identities hold in all 36 (n, target, K, L) cases; two misuse modes documented)

Implementation: `shardCnt` counts level-`L` nodes in DFS order (deterministic), shard `i` explores the subtree of the
level-`L` nodes with index `≡ i (mod K)`; nodes at levels `<= L` are visited (and counted) by every shard.
`referee_forest_diff.py` section C, n = 10, 11, 12 × {standard, planted} × (K,L) ∈ {(3,6), (7,5), (5,4), (13,8), (4,9),
(1000,7)} — including K not dividing the number of level-L nodes (e.g. n=12 L=8: 58 933 ≡ 4 mod 13; L=7: 8 877 ≡ 877 mod
1000; L=9: 278 539 ≡ 3 mod 4) and K > #level-L nodes: for every depth `d <= L` each shard's histogram entry equals the full
run's; for `d > L` the shard entries sum exactly to the full run's; `Σ nsol = nsol`; `Σ nodes = K·prefix(<=L) + (total -
prefix)`. n=18 production layout (K=512, L=8): 62 843 level-8 subtrees (Python-verified), ~123 per shard.
Misuse modes (not bugs, but the certificate must exclude them): (i) `L >= E` (or `L` beyond the deepest live level, e.g.
n=10, L=9): every shard explores the whole tree — the K-fold overcount is conservative for a "0" verdict but not for counts;
(ii) `--shard i K` with `i >= K`: silently explores the prefix only and reports `nsol 0` (n=10: 282 nodes); (iii) unknown
flags are silently ignored (`--shrad 1 3` runs the unsharded search; visible in the JSON `shard` triple `[0,1,8]`);
(iv) `--nodes` abort gives `"status": "UNKNOWN"`, which `run_forest.py`'s resume logic treats as done. Consequently the
verdict script must assert: exactly K records, `shard[1:] == [K, L]` for all, `{shard[0]} == {0..K-1}`, all `DONE`.
Current local n=18 file (checked at 265/512): all `DONE`, `[512, 8]`, no duplicate index, `nsol 0`.

## 8. Certificate scheme for the n=18 verdict — recommendation

What the verdict rests on: (i) forcing lemma (proof, Section 2, standard); (ii) exactly-once generation (proof + Python
oracle to n=12 and to level 9 at n=18); (iii) prefilters exact (Python oracle, planted witnesses to n=18); (iv) shard
partition (Section 5); (v) faithful execution of 512 shard processes. (i)–(iv) are now audited; (v) is where the
certificate must work. Concretely:

1. **Per-shard records must carry the depth histogram.** The engine prints it to stderr; `src/run_forest.py` discards
   stderr (`capture_output=True`, only stdout parsed), so the local n=17 and n=18 runs have **no per-level counts** — the
   strongest cheap integrity check is lost. `scripts/hoffman2_forest_array.sh` keeps stderr in `logs/`; use those, or
   re-run locally with stderr saved. Then check, over all K shards: `hist_i[d] == prefix[d]` for `d <= 8` (prefix =
   1,1,2,8,41,229,1384,8899,62843 — Python-verified) and `Σ_i hist_i[d]` for `d = 9..12` equals the exact whole-tree
   counts obtained here (n=18: L9 = 480 085 (Python-verified), L10 = 3 984 162, L11 = 35 540 837, L12 = 332 597 341;
   n=17: 480 084 / 3 983 102 / 35 234 962 / 303 618 177). Any lost, duplicated or truncated shard breaks these sums.
2. **Verdict script** (add to `run_forest.py` or a `verify_forest_run.py`): exactly K records, identical `[K, L]`, indices
   `0..K-1` each once, all `status DONE`, `Σ nsol`, `Σ nodes − (K−1)·73 408` = unique nodes; record engine source
   sha256, binary md5, compiler, host per record (currently none of these is recorded).
3. **Independent replication:** Hoffman2 run (gcc, different CPU) with a **different** shard layout (e.g. K=1024, L=9):
   node counts are deterministic, so `unique nodes` and every per-level sum must agree bit-for-bit with the local run;
   both `nsol = 0`. This detects machine/compiler faults, not algorithmic ones.
4. **Independent method:** the per-topology engine v2 on Hoffman2 over the 123 867 (or 122 344 surviving) topologies is
   an independent formulation (its own symmetry breaking and prunes, audited in `docs/referee-report.md`); its cost is
   1e4–1e5 CPU-h. A cheaper independent replication is a *second implementation of the forest search from the algorithm
   description* (not from `forest_search.cpp`; C/Rust; ~10 CPU-h) required to reproduce the per-level counts, which are a
   mathematical invariant (number of abstract forced forests per level, Section 1) — agreement of all 18 per-level counts
   is far stronger evidence than agreement of a single "0".
5. **Prefix oracle deeper:** the Python oracle reaches level 9 in 2.5 min; a compiled canonical-form dedup oracle could
   check levels 10–11 (4e6 / 3.6e7 forests) against the shard sums with modest memory.
6. For a **SAT** outcome nothing more is needed: `SOL` lines are re-checked by `checker_a/checker_b` in the driver.
